# Цифровой двойник трубопрокатного агрегата

Интерактивная визуализация производства **бесшовных стальных труб**, собранная для демонстраций
APS / MRP, семинаров по теории ограничений, объяснения планирования поставок, обучения персонала
и конференций.

Это не сайт. Это детерминированная имитационная модель производства с цехом, отрисованным на 60 fps.

- **Язык интерфейса:** русский (Онлайн / Сравнение / Презентация / Анатомия / Материалы).
- **Дизайн-система:** In.Plan — Open Sans, брендовый фиолетовый `#9000FF` на холсте `#F5F6F8`,
  плоские радиусы 4 px / 8 px, иконки In.Plan и белый логотип `in.plan`. Токены живут в
  `tailwind.config.js`, `src/core/constants.ts`, `src/styles/index.css` и
  `src/components/ui/icons.tsx`.
- **Графика:** всё оборудование, продукт и разрезы — рисованный inline-SVG, растровых ассетов нет
  (кроме логотипа). Состояние (простой/работа/блокировка/…) передаётся рамкой карточки, счётчиками
  и обесцвечиванием в режиме ТОС, а не перерисовкой оборудования. Металл меняет цвет по ходу
  передела: холодная заготовка серая, после кольцевой печи — оранжевая, после холодильника снова
  сталь.

## Быстрый старт

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # проверка типов + продакшн-сборка в dist/
npm run preview  # раздача продакшн-сборки
npm run check    # типы + проверка модели + headless-рендер
```

### Маршрут: ТПА с непрерывным станом

```
Склад заготовки → Кольцевая печь (1250 °C) → Прошивной стан (гильза) →
Непрерывный стан PQF (раскатка на оправке) → Редукционный стан → Холодильник →
Правка → Контроль (УЗК, ЭМК, гидроиспытание) → Резка и торцовка →
Буферный карман → Нарезка резьбы → Готовая продукция
```

Вариант «Премиум-соединение» достраивает ветку: **Навинчивание муфт → Контроль резьбы →
Пакетирование**.

### Варианты продукта

| Вариант | Продукт | Отличия |
| --- | --- | --- |
| **Обсадная** (базовый) | 168,3 × 8,94 J55, резьба BTC | Эталонный такт: резьба 14 мин на 4 станках. |
| **НКТ** | 73,0 × 5,51 L80, резьба NU | Меньше диаметр: быстрее прошивка, раскатка и резьба. |
| **Премиум** | 244,5 × 11,99 P110, премиум-соединение | Длиннее цикл, три дополнительных передела, свой уплотнительный узел. |
| **Микс** | Смешанный поток | Портфель заказов, маршрутизация по типу, переналадка инструмента, FIFO против кампаний. |

### Сюжет теории ограничений, проверяемый автоматически

`npm run verify` прогоняет модель headless и утверждает основную историю:

```
baseline (4 machines)   thr  17.0/h  cycle  111m  wip 48  queue 31  buffer 25  thread 100%  bottleneck Нарезка резьбы
optimised (8 machines)  thr  24.0/h  cycle   51m  wip 20  queue  0  buffer  0  thread  71%  bottleneck —
```

Горячий передел выдаёт трубу примерно раз в полторы минуты, а резьбонарезному станку нужно
14 минут на трубу. На четырёх станках агрегат отдаёт 17 труб/ч, и в кармане перед резьбой копится
очередь. Удвоение числа станков рассасывает очередь, выводит выработку на план и сокращает время
цикла более чем вдвое.

Тот же скрипт проверяет, что живой прогон, накормленный *дёргаными кадрами браузера*, приходит
ровно в то же состояние, что и `seek()`, воспроизводящий смену одним шагом; что закадровый текст
зацикливается, а не замирает на последней реплике; и что достижимы все четыре состояния ресурса.

### Универсальный движок производственной визуализации

Движок намеренно ничего не знает о трубах. Завод описывается как **Ресурсы, Буферы, Маршруты,
Заказы и События**, а трубопрокатный агрегат — это всего лишь
`src/scenarios/seamless-pipe-mill.json`. Шины, напитки, фарму или FMCG можно добавить, положив
рядом другой файл сценария и зарегистрировав его в `src/core/scenario.ts` — без изменений в
движке и компонентах.

Каждый узел сценария объявляет геометрию, рендерер оборудования, время обработки, параллельную
мощность, ёмкость очереди, время транспортировки и ползунок, который им управляет.

Сам продукт — тоже данные: `construction` (элементы конструкции), `assemblyLayers`
(последовательность формоизменения), `composition` (химсостав марки) и `materials` (структура
затрат) наполняют вкладки «Анатомия» и «Материалы» без единой зашитой строки в компонентах.

### Модель

* Фиксированный шаг `TICK_MINUTES = 0.1` модельной минуты. Часы выводятся из целочисленного
  счётчика тиков, а неполные кадры браузера накапливаются, поэтому живой прогон и воспроизведение
  через `seek()` дают идентичное состояние — перемотка никогда не переписывает историю.
* На скорости 1x одна реальная секунда равна двум модельным минутам.
* Единицы резервируются в очереди следующего передела до отправления, поэтому заполненный
  буфер даёт настоящее состояние **«заблокирован»**, а не исчезающую трубу.
* Состояния ресурса: `idle` (ждёт, материал в пути), `working`, `blocked` (следующий передел
  заполнен), `starved` (нет входа), плюс производное `bottleneck` и `changeover` в смешанном потоке.
* Загрузка — экспоненциальное скользящее среднее (τ = 15 мин), поэтому она реагирует на живое
  изменение параметров, а не тянет за собой историю.
* Ограничение — ресурс с наибольшим сочетанием загрузки и давления очереди; очередь, которую
  держит непосредственно предшествующий буфер, приписывается ему, и режим ТОС подсвечивает этот
  буфер вместе с самим ограничением.
* KPI пересчитываются каждые 100 мс, канвас перерисовывается каждый кадр анимации.

### Рендеринг на 60 fps

Состояние публикуется через три раздельных контекста, чтобы частота кадров канваса не диктовала
стоимость перерисовки остального интерфейса:

| Контекст | Частота | Потребители |
| --- | --- | --- |
| `SimulationControls` | только по действию пользователя | Header, ползунки, переключатели режимов |
| `SimulationFrame` | каждый кадр анимации | ProductionCanvas, таймлайн |
| `SimulationKpi` | каждые 100 мс | карточки KPI, график, оверлей APS |

Рисунки оборудования мемоизированы, поэтому анимации машин не перезапускаются при обновлении
канваса, а перемотка таймлайна коалесцируется до одного воспроизведения на кадр.

## Соблюдённые ограничения дизайна

* Никакого Bootstrap и компонентных фреймворков — каждый контрол написан вручную.
* Никаких нативных `<button>`, `<input type="range">` и `<select>`; всё взаимодействие идёт через
  примитивы `Pressable`, `RangeControl` и `Segmented` с поддержкой клавиатуры (стрелки, Home/End,
  PageUp/PageDown) и корректными ролями ARIA.
* Каждый файл остаётся короче 300 строк; все параметры проходят через React Context.
* Все константы живут в `src/core/constants.ts`.

## Контроль качества

```bash
npm run typecheck   # строгий TypeScript, без неиспользуемых локальных переменных и параметров
npm run verify      # headless-модель: детерминизм, сюжет ТОС, закадровый текст, состояния
npm run smoke       # поднимает настоящее приложение в jsdom, жмёт Пуск, ТОС и APS
npm run check       # все три
npm run build       # проверка типов + продакшн-сборка
```

Smoke-тест дополнительно проверяет, что ни один нативный `<button>` или `<input>` не попадает в DOM
и что на канвасе нет ни одного растрового `<image>`.

## Рабочие заметки для новой сессии

**Где что лежит.** Приложение — это корень репозитория `C:\Git\steel pipes`. Все команды `npm`
запускаются отсюда.

**Запуск.**

```bash
npm install          # первый раз (Node 20+, npm)
npm run dev -- --port 5175 --host
```

Либо через превью-браузер: `.claude/launch.json` объявляет `pipes-dev` (5175) и `pipes-preview`
(4175) — вызовите `preview_start` с этим именем. После изменения `tailwind.config.js` **перезапустите
дев-сервер** — HMR не подхватывает изменения конфигурации Tailwind.

**Проверка визуальных изменений.** Панель браузера часто не композитит кадры: скриншоты отваливаются
по таймауту, а цикл rAF придушен, поэтому модельные часы стоят. Не полагайтесь на скриншоты — читайте
DOM через `read_page` / `get_page_text` / `javascript_tool`.

Чтобы **посмотреть на рисунок**, отрендерьте канвас или разрез в самостоятельный SVG:

```bash
npm run render -- casing 200 canvas.svg     # цех через 200 модельных минут
npm run render -- premium anatomy pipe.svg  # разрез трубы премиум-группы
```

SVG конвертируется в PNG через `sharp` (ставится на время: `npm install --no-save sharp`).

## Развёртывание

`vite.config.ts` задаёт `base: '/steel-pipes/'` только для продакшн-сборки (дев остаётся на `/`).
Для публикации на GitHub Pages добавьте workflow, запускающий `npm ci && npm run build` и
публикующий `dist/`; бесплатные Pages обслуживают только **публичные** репозитории — иначе Vercel,
Netlify или Cloudflare Pages (там `base` можно вернуть к `/`).
